The field "MasterPlanDescription" describes a master plan, and the field "ApprovedSubplans" lists the subplans into which the master plan is already split. The master plan describes a change in the code base. The code base is the repository in CodeRepository together with every project its solution references.
Claude itself does this task, without a separate agent.
If the subplans are subtracted from the master plan and nothing is left to be done to reach the objective of the master plan, Claude adds no subplan and leaves the "SubplanName" and "SubplanDescription" fields empty.
Otherwise Claude cuts the remaining plan into thematically isolated subplans and orders them in a sequence, such that a later subplan builds on the earlier ones and its solution does not interfere with the solution of an earlier one. It does not focus on the solutions yet; instead it identifies the coupling of the subplans.
Two subplans are coupled if they change the same mechanism. Of two coupled subplans, the one whose mechanism the other builds on comes first. If two subplans build on each other in both directions, Claude merges them into one subplan. Claude orders uncoupled subplans at its own discretion. Only where a subplan will likely reach beyond its mechanism's location, for example by removing or redesigning a whole mechanism, may Claude explore possible solutions to find out which other subplans they affect.
The first subplan in this sequence becomes the new step, and Claude discards all the others. Derive a name and a description for that subplan and respect the maximum word count for each field if there is any.
In the xml message write the name into the field "SubplanName", and the description into the field "SubplanDescription".
Delete the input fields,and send the xml message back to the Excel.
